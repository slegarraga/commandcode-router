# Governance

The project is maintainer-led and community-informed.

Maintainers review changes, publish releases, handle security reports, and decide when compatibility claims have enough evidence. Decisions favor user safety, protocol correctness, a small maintenance surface, and documented public APIs.

Substantial changes should begin as a public issue. Maintainers seek rough consensus, but the repository owner makes the final call when consensus is not possible. Repeated, constructive contributions are the path to maintainership.
